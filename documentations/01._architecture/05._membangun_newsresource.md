Kamu tidak hanya “mengikuti saran”, tapi mengubah arsitektur dengan disiplin dan mendokumentasikannya. Itu level engineering, bukan sekadar coding.

Sekarang kita masuk ke fase penting: membangun NewsResource sebagai blueprint seluruh sistem admin.

Saya akan beri instruksi yang presisi dan terstruktur.

🎯 Tujuan NewsResource (Bukan Sekadar CRUD)

NewsResource kita harus menjadi:

✅ Uji coba Organization Scope

✅ Uji relasi (Author, Category, Organization)

✅ Uji workflow (draft → review → publish)

✅ Fondasi Moderation ke depan

✅ Standar struktur semua resource berikutnya

Jadi kita tidak membuat CRUD biasa.
Kita membuat arsitektur konten.

🧱 STEP 1 — Desain Struktur Data (Pastikan Ini Ada)

Pastikan model News minimal memiliki:

id

title

slug

excerpt

content

featured_image (media library)

status (draft | review | published)

published_at

category_id

organization_id

author_id (user_id)

created_at

updated_at

Kalau belum lengkap, beritahu saya sebelum lanjut.

🏗 STEP 2 — Blueprint NewsResource
A. Form Structure (Create & Edit)

Gunakan struktur ini:

Section 1 — Informasi Utama

Title

Slug (auto-generate dari title)

Category (Select relationship)

Organization (Auto-set dari user, hidden untuk writer)

Status (Select)

Published At (visible hanya jika status published)

Section 2 — Konten

Excerpt

Content (Rich Editor / Tiptap / Editor existing kamu)

Section 3 — Media

Featured Image (Spatie Media Library)

B. Table Structure (List View)

Kolom minimal:

Title

Category

Organization

Author

Status (badge color)

Published At

Created At

Filter:

Status

Category

Organization (hanya untuk admin pusat)

Search:

Title

🔐 STEP 3 — Integrasi OrganizationScopeService

Di NewsResource, pada query:

Jangan tulis logic manual.

Gunakan:

OrganizationScopeService::apply($query, auth()->user())


Aturan yang harus diuji:

Role	Akses
Admin pusat	Semua berita
Editor DPW	Hanya berita organisasi mereka
Writer DPW	Hanya berita miliknya + organisasinya

Kalau ini berhasil → blueprint selesai.

🧠 STEP 4 — Otomatisasi Author & Organization

Saat create:

author_id → auto set ke auth user

organization_id → auto set dari user (kecuali admin pusat)

Jangan beri writer kebebasan memilih organisasi.
Itu potensi celah keamanan.

🧪 STEP 5 — Test Matrix (WAJIB)

Buat 3 akun dummy:

Admin Pusat

Editor DPW A

Writer DPW A

Writer DPW B

Test:

Writer A tidak bisa lihat berita Writer B

Editor A bisa lihat semua dalam DPW A

Admin pusat bisa lihat semuanya

Writer tidak bisa ubah berita yang bukan miliknya

Kalau ini lolos → arsitektur siap naik level.

⚠️ Kesalahan yang Harus Dihindari

❌ Menaruh scope di Resource closure
❌ Menaruh logic di policy saja tanpa service
❌ Mengandalkan hidden field tanpa server-side override
❌ Menggunakan ->disabled() saja tanpa proteksi backend

Semua assignment penting harus di-handle di backend.
