# Blueprint Modul Shop / E‑Shop IKA UNIMED

## 1. Tujuan & Lingkup

- Menyediakan blueprint arsitektur untuk modul Shop / E‑Shop resmi IKA UNIMED (single‑vendor).
- Menyelaraskan modul Shop dengan arsitektur hybrid yang sudah ada:
  - Filament = Governance Layer (manajemen katalog, pesanan, laporan).
  - Inertia = Application Layer (frontstore, cart, checkout).
- Menentukan domain, model inti, permission, serta pemetaan UI (Filament vs Inertia).
- Menyiapkan integrasi payment gateway via Tripay (menghubungkan ke Midtrans) dengan pola webhook teruji.


## 2. Asumsi Arsitektur Utama

- Single‑vendor shop:
  - Toko resmi dikelola oleh IKA UNIMED (bukan marketplace multi‑penjual).
  - Pengembangannya tetap membuka kemungkinan eskalasi ke multi‑vendor di masa depan.
- Payment Gateway:
  - Frontend transaksi menggunakan Tripay sebagai payment aggregator.
  - Backend tetap mengacu ke standar keamanan & webhook Midtrans (signature verification, status update, dll).
- Hybrid Layer:
  - Filament Admin Panel hanya untuk governance:
    - Manajemen produk, stok, harga, kategori, pesanan, dan laporan.
  - Inertia Dashboard / halaman publik untuk aplikasi:
    - Katalog produk, detail produk, cart, checkout, riwayat pesanan pengguna.
- RBAC (Spatie):
  - Sumber kebenaran akses hanya dari Spatie roles & permissions.
  - Namespace permission baru: `shop.*`.
  - `users.role` hanyalah legacy/fallback, tidak digunakan untuk mengontrol akses Shop.
- Scope organisasi:
  - Fase awal: Shop bertindak sebagai toko global (tidak dibatasi per organisasi).
  - Fase lanjutan: bisa ditambah `organization_id` pada produk/pesanan bila ingin Shop per‑organisasi.

### 3.2 Detail Field Utama (Ringkasan)

**Product**

- `id`
- `name`
- `slug`
- `description`
- `price` (integer, dalam rupiah)

- `stock` (integer, bisa 0 untuk preorder)

- `category_id` (nullable)
- `organization_id` (nullable, untuk masa depan)

**Order**

- `id`
- `user_id`
- `status` (enum: `pending`, `awaiting_payment`, `paid`, `processing`, `shipped`, `completed`, `canceled`)
- `total_amount`
- `shipping_cost`
- `grand_total`
- `shipping_address` (JSON atau relasi ke tabel `ShippingAddress`)
- `notes` (catatan dari pembeli)

**Payment**

- `id`
- `order_id`
- `provider` (`tripay`, `midtrans`, dll.)
- `provider_reference` (kode/ID dari Tripay/Midtrans)
- `method` (bank/ewallet)
- `amount`
- `status` (enum: `pending`, `paid`, `failed`, `expired`)
- `paid_at` (nullable)
- `raw_payload` (JSON ringkas)

## 5. Pemetaan UI: Filament vs Inertia

### 5.1 Filament (Governance Layer)

| Resource / Page                       | Layer     | Akses minimal                            | Deskripsi                                                                                      |
|--------------------------------------|-----------|------------------------------------------|------------------------------------------------------------------------------------------------|
| `Shop\ProductResource`               | Filament  | `shop.product.view`                      | Manajemen produk (list, create, edit, archive).                                                |
| `Shop\ProductCategoryResource`       | Filament  | `shop.category.manage`                   | Manajemen kategori produk.                                                                     |
| `Shop\OrderResource`                 | Filament  | `shop.order.view`                        | List semua pesanan, detail order, filter by status, export sederhana.                         |
| `Shop\OrderResource` (aksi status)   | Filament  | `shop.order.manage`                      | Aksi ubah status: processing, shipped, completed, canceled.                                   |
| `Shop\PaymentResource`               | Filament  | `shop.payment.view`                      | Melihat daftar payment, status, dan log.                                                       |
| `Shop\ShopSettingResource`           | Filament  | `shop.settings.manage`                   | Konfigurasi shop: fee, pajak, teks panduan pembayaran, dsb.                                   |

Semua resource Filament ini mengikuti pola yang sudah ada:

- `canViewAny()` → cek permission `shop.*` yang relevan.
- `canCreate()`, `canEdit()`, `canDelete()` → diatur sesuai matrix (admin vs editor vs operator).


### 5.2 Inertia (Application Layer)

| Fitur / Halaman                     | Route                                    | Akses                                     | Deskripsi                                                                                  |
|-------------------------------------|------------------------------------------|-------------------------------------------|--------------------------------------------------------------------------------------------|
| Katalog Produk                      | `GET /shop` → `shop.index`              | Publik                                    | Menampilkan daftar produk aktif (`Product.is_active = true`).                              |
| Detail Produk                       | `GET /shop/{product:slug}`              | Publik                                    | Menampilkan detail produk + tombol tambah ke cart.                                         |
| Cart                                | `GET /shop/cart`                        | Auth (subscriber/learner/user terdaftar)  | Menampilkan isi cart user (disimpan di session atau DB).                                  |
| Checkout                            | `GET /shop/checkout`                    | Auth                                      | Form konfirmasi alamat, ringkasan pesanan, pilihan metode pembayaran.                     |
| Checkout (submit)                   | `POST /shop/checkout`                   | Auth                                      | Membuat `Order` + `Payment`, memanggil API Tripay, redirect ke halaman pembayaran.        |
| Riwayat Pesanan                     | `GET /shop/orders`                      | Auth                                      | Menampilkan list pesanan milik user (policy: `Order.user_id = auth()->id()`).             |
| Detail Pesanan                      | `GET /shop/orders/{order}`              | Auth                                      | Menampilkan detail 1 pesanan (policy per‑user).                                            |

Integrasi dengan dashboard yang sudah ada:

- Untuk subscriber/learner:
  - Link ke `/shop` bisa muncul di sidebar dashboard Inertia (group baru, misal: `SHOP / MARKETPLACE`) dengan permission implisit “siap checkout” (subscriber aktif).
- Untuk admin/operator:
  - Akses operasional admin tetap lewat Filament (`/admin`) → `Shop\OrderResource` dll.


## 6. Alur Payment dengan Tripay + Midtrans

### 6.1 Sequence Checkout (Frontend → Backend → Tripay)

1. User mengisi cart dan membuka halaman Checkout (`GET /shop/checkout`).  
2. User mengirim form (`POST /shop/checkout`):
   - Backend memvalidasi data.
   - Membuat `Order` (status awal `pending` atau `awaiting_payment`).
   - Menghitung total, ongkir, grand total.
   - Membuat `Payment` terkait order tersebut (status `pending`).
3. Backend memanggil API Tripay:
   - Mengirim detail order, jumlah, callback URL (webhook), dan return URL.  
   - Menerima `provider_reference` / payment URL.
   - Menyimpan `provider_reference` di `Payment`.
4. Backend redirect user ke halaman pembayaran Tripay.


### 6.2 Webhook & Update Status

1. Tripay mengirim callback ke endpoint webhook, misalnya:
   - `POST /webhook/tripay/shop`.
2. Controller webhook:
   - Verifikasi signature (berdasarkan dokumentasi Tripay dan standar keamanan yang selaras dengan Midtrans).
   - Temukan `Payment` berdasarkan `provider_reference`.
   - Update `Payment.status` (`paid` / `failed` / `expired`) dan `paid_at` jika sukses.
   - Update `Order.status`:
     - Jika payment `paid` → `status = paid` (atau langsung `processing`).
     - Jika `failed/expired` → `status = canceled` (atau `awaiting_payment` khusus retry).
3. Simpan payload lengkap di `PaymentLog` untuk audit & debugging.
4. Opsional: kirim notifikasi (email/notification) ke user dan/atau admin.


### 6.3 Prinsip Keamanan

- Webhook selalu diverifikasi signature‑nya sebelum mengubah status internal.
- Tidak ada log yang menyimpan credential rahasia; hanya payload dan reference yang aman.
- Semua perubahan status order yang terkait pembayaran **hanya** lewat alur ini, bukan lewat UI biasa.


## 7. Roadmap Implementasi Bertahap

### Fase 1 – Katalog Produk (Read‑only)

- Model & migrasi:
  - `Product`, `ProductCategory`, `ProductImage` (field minimal).
- Filament:
  - `ProductResource`, `ProductCategoryResource` dengan `shop.product.view/manage` dan `shop.category.manage`.
- Inertia:
  - Halaman `/shop` (list produk aktif) dan `/shop/{slug}` (detail produk).
- Belum ada cart/checkout, hanya showcase.


### Fase 2 – Cart & Checkout (Tanpa Payment Sungguhan atau Mode Sandbox)

- Tambah model `Order`, `OrderItem` (tanpa integrasi payment dulu, atau gunakan sandbox Tripay).
- Implementasi cart dan checkout di Inertia.
- Order tersimpan dengan status `pending` / `awaiting_payment`, tapi belum terhubung ke Tripay secara penuh (boleh mulai dari dummy).


### Fase 3 – Integrasi Tripay + Webhook

- Tambah model `Payment`, `PaymentLog`.
- Integrasikan endpoint Tripay:
  - Pembuatan channel pembayaran saat checkout.
  - Endpoint webhook yang mengupdate `Payment` dan `Order`.
- Tambah `Shop\OrderResource` dan `Shop\PaymentResource` di Filament untuk melihat pesanan dan payment.


### Fase 4 – Pengayaan & Ekspansi

- Tambah fitur:
  - `ShopSettingResource` untuk konfigurasi global Shop.
  - Varian produk (`ProductVariant`) jika diperlukan (ukuran, warna).
  - Filter katalog (kategori, harga, tekstual).
- Opsional:
  - Tambah `organization_id` pada `Product` dan `Order` untuk mendukung Shop per‑organisasi, dengan scope mirip `OrganizationScopeService`.


## 8. Integrasi dengan Blueprint RBAC & Dashboard Eksisting

- Semua akses Shop di Filament mengacu pada permission `shop.*` (Spatie).
- Sidebar Inertia menambahkan grup baru, misalnya `SHOP / MARKETPLACE`, yang:
  - Muncul untuk user dengan konteks pembeli (subscriber, learner, alumni yang sudah melengkapi profil).
  - Tetap mematuhi pola `SIDEBAR_MENU` berbasis permission / policy.
- Payment & donasi tetap konsisten dengan standar gateway yang sudah digunakan sebelumnya (Midtrans), melalui Tripay sebagai lapisan aggregator untuk modul Shop.

# 📦 5. Stok & Race Condition

Sekarang:

```
Product.stock (integer)
```

Masalahnya:
Jika 2 orang checkout bersamaan, bisa oversell.

Saran:

Saat checkout submit:

```
DB::transaction():
    - Lock product row (SELECT FOR UPDATE)
    - Cek stok
    - Kurangi stok
```

Dan simpan stok snapshot di OrderItem.

Ini bagian penting.

Jangan berdiri sendiri.

---

## Skenario 1: Belajar → Belanja

User beli course →
Dapat diskon merchandise →
Dapat penawaran membership premium

---

## Skenario 2: Event → Donasi

User ikut webinar gratis →
Di akhir muncul campaign donasi beasiswa

Conversion rate biasanya tinggi.

---

## Skenario 3: Donasi → Badge Sosial

User donasi > Rp 1 juta →
Dapat badge “Alumni Dermawan” di profil

Gamifikasi meningkatkan kontribusi.

---

## Skenario 4: Shop sebagai Channel Donasi

Tambahkan:

Checkbox saat checkout:

☑ Tambah donasi Rp 10.000 untuk beasiswa

Ini efektif.

# 🏗 6. Model Revenue Architecture Ideal

Struktur final:

```
Core Revenue:
- Course Paid (LMS)
- Corporate Training

Supporting Revenue:
- Merchandise
- Digital product

Sustainable Revenue:
- Recurring donation
- Membership premium
```

Kalau diprioritaskan:

1️⃣ LMS berbayar
2️⃣ Recurring donation
3️⃣ Digital product
4️⃣ Merchandise

---

# 📊 7. Proyeksi Realistis (Simulasi)

Misal:

* 500 alumni beli course rata-rata Rp 250.000
  → 125 juta

* 1000 alumni donasi Rp 25.000/bulan
  → 25 juta/bulan

* Merchandise 300 pcs x margin 50k
  → 15 juta

Total potensi awal:
150–200 juta / periode campaign

Untuk organisasi alumni, ini sudah kuat.

---

# ⚠ 8. Kesalahan yang Harus Dihindari

❌ Fokus hanya ke merchandise
❌ Tidak punya campaign narrative
❌ Tidak transparan penggunaan dana
❌ LMS gratis semua tanpa monetisasi
❌ Tidak ada recurring revenue

---

# 🧭 9. Urutan Eksekusi Paling Rasional

Tahap ideal untuk IKA UNIMED:

1. Stabilkan Shop basic (katalog + checkout)
2. Tambahkan Donasi Campaign
3. Launch 1 course premium pilot
4. Tambahkan membership premium
5. Bangun recurring donation
