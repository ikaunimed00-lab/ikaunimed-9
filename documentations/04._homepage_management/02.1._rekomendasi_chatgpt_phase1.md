Ini keputusan paling benar di seluruh blueprint.

# ⚠️ Refinement Penting (Agar Lebih Future-Proof)

Sekarang saya masuk ke bagian kritis.

---

## 🔧 1️⃣ Enum `type` → Saya Sarankan Jangan Enum

Blueprint sekarang:

```
type ENUM ('hero','cta','video','features','packages')
```

Masalah:

Kalau nanti Anda ingin tambah:

* testimonials
* partners
* statistics
* campaign_banner

Anda harus:

* edit migration
* alter enum
* redeploy

Itu tidak fleksibel.

### Lebih Baik:

Gunakan:

```
type VARCHAR
```

Validasi type di level aplikasi, bukan DB.

Itu jauh lebih scalable.

---

## 🔧 2️⃣ Kolom `title` di homepage_sections

Blueprint:

```
title = Judul internal untuk manajemen admin
```

Ini bagus.

Tapi saya sarankan tambahkan juga:

```
slug (nullable)
```

Kenapa?

Kalau nanti:

* Homepage jadi multi-landing
* Ada anchor link (#features)
* Ada preview link

Slug akan sangat berguna.

---

## 🔧 3️⃣ Tambahkan `scope_type` & `scope_id` (Future Proof)

Walaupun sekarang global-only, saya sangat sarankan tambahkan:

```
scope_type (default: global)
scope_id (nullable)
```

Contoh future:

* global
* dpw
* dpc

Walaupun belum dipakai, ini menyelamatkan Anda dari migrasi ulang besar nanti.

---

## 🔧 4️⃣ site_settings → Jangan Over-Generic

Tabel ini key-value. Bagus.

Tapi hati-hati jangan sampai jadi:

“Garbage drawer table”

Saran saya:

Gunakan group dengan tegas:

* identity
* contact
* social
* footer
* seo

Dan batasi via Filament form.

Jangan biarkan admin menambah key sembarangan.

---

## 🔧 5️⃣ Cache Strategy – Perjelas

Blueprint bilang:

> Cache di-clear otomatis

Bagus.

Tapi lebih profesional kalau:

Gunakan:

```
Cache::tags(['site_settings'])
Cache::tags(['homepage'])
```

Supaya bisa clear per-group.

Itu enterprise-level.
