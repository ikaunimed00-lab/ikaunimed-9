# Blueprint Role, Permission, dan Menu Dashboard

## 1. Tujuan Dokumen

- Merangkum keputusan akhir dari diskusi panjang tentang role, permission, dan menu dashboard.
- Menyusun langkah implementasi yang rapi dan bisa dieksekusi bertahap.
- Menjadi acuan tunggal saat mengubah menu dashboard dan akses di Filament maupun Inertia.

## 2. Keputusan Arsitektur yang Sudah Disepakati

- Semua manajemen backoffice (CMS, kursus, master data, site settings) masuk ke Filament.
- Pengalaman pengguna (belajar, portal subscriber, tampilan publik) tetap di Inertia.
- Sistem akan dikelola tim besar dengan pemisahan kewenangan yang ketat.
- Role akan dipisah berdasarkan domain dan bersifat multi-role (satu user bisa punya lebih dari satu role).
- Akan digunakan Spatie Laravel Permission untuk mengelola roles dan permissions.

## 3. Domain, Role, dan Scope

### 3.1 Domain Utama

- CMS: news, scholarships, job vacancies, program content.
- Site Management: homepage sections, site settings.
- E-Learning: course, lesson, enrollment, participant.
- Alumni & Direktori: profil alumni, direktori, kabar alumni.
- Community & Moderation: alumni posts, reports.
- Master Data: users, organizations, roles.
- Portal: pengalaman subscriber (profil, kelas, lamaran).

### 3.2 Role Final

- System roles:
  - super_admin
  - admin
- Domain roles:
  - editor (CMS)
  - writer (CMS)
  - instructor (E-Learning)
  - moderator (Community/Alumni)
  - subscriber (Portal)

### 3.3 Scope

- Scope organisasi tetap seperti sekarang:
  - pengurus_pusat
  - pengurus_wilayah
  - pengurus_cabang
- Scope akan diatur melalui policy dan query (bukan di permission string).

## 4. Konvensi Penamaan Permission

- Pola: `domain.entity.action`
- Contoh:
  - cms.news.create
  - cms.news.publish
  - elearning.course.edit
  - site.settings.edit
  - master.users.assign_role

Konvensi ini akan digunakan saat mendefinisikan permission Spatie dan memetakan ke Filament policies.

## 5. Matrix Role → Domain → Permission (Ringkas)

### 5.1 CMS

- Entitas: news, scholarships, job_vacancies, program_content.
- Writer:
  - cms.news.view, cms.news.create, cms.news.edit
  - cms.scholarship.view/create/edit
  - cms.job.view/create/edit
  - Tidak boleh publish.
- Editor:
  - Semua hak writer pada domain CMS.
  - cms.news.publish, cms.scholarship.publish, cms.job.publish.
- Admin:
  - Semua permission CMS tanpa batas scope.

### 5.2 Site Management

- Entitas: homepage, site_settings.
- Admin:
  - site.homepage.view/edit
  - site.settings.view/edit
- Editor (opsional, tergantung kebijakan final):
  - site.homepage.view/edit
- Writer:
  - Tidak memiliki permission site management.

### 5.3 E-Learning

- Entitas: course, lesson, enrollment, participant.
- Instructor:
  - elearning.course.view/edit (hanya course milik sendiri).
  - elearning.enrollment.view (hanya course milik sendiri).
  - elearning.participant.view (hanya course milik sendiri).
- Editor:
  - elearning.course.create/edit/publish.
  - elearning.course.assign_instructor.
- Admin:
  - Semua permission elearning.

### 5.4 Alumni, Community, Master Data, Portal

- Alumni & Direktori:
  - Moderator: alumni.moderate, alumni_post.moderate.
  - Admin: semua permission alumni/direktori.
- Community:
  - Moderator: post.moderate, report.handle.
  - Admin: semua community permission.
- Master Data:
  - Admin: users.manage, organizations.manage.
  - Super Admin: termasuk roles.manage.
- Portal:
  - Subscriber: portal.profile.edit, portal.enroll.course, portal.enrollment.view_own.

## 6. Roadmap Implementasi Teknis (Fase Bertahap)

### Fase 1 – Menambahkan Multi-Role Tanpa Merusak Sistem Lama

- Menambahkan tabel dan model:
  - Buat tabel `roles` dan `permissions` sesuai Spatie.
  - Buat pivot `model_has_roles`, `model_has_permissions`, `role_has_permissions` (standard Spatie).
- Migrasi role lama:
  - Mapping `users.role` lama → role Spatie:
    - admin → admin
    - editor → editor
    - writer → writer
    - subscriber → subscriber
  - Setiap user lama mendapat satu role di Spatie sesuai kolom `users.role`.
- Pertahankan kolom `users.role` dan semua method lama (`isWriter()`, dll) agar sistem tetap berjalan.

### Fase 2 – Helper Baru di Model User

- Tambahkan relasi dan helper:
  - `roles()` (belongsToMany ke Role).
  - `hasRole()` / `hasAnyRole()` / `hasPermissionTo()` dari Spatie.
- Mulai refactor bertahap:
  - Ubah pengecekan dari `role === 'admin'` menjadi `hasRole('admin')`.
  - Biarkan helper lama tetap ada selama masa transisi.

### Fase 3 – Pengaturan Filament dan Menu Dashboard

- Filament:
  - Tambah `canViewAny()` di resource:
    - OrganizationProgramResource → hanya admin (+ editor jika disetujui).
    - HomepageSectionResource → admin (+ editor jika disetujui).
    - SiteSettingResource → hanya admin.
  - Nantinya, `canViewAny()` akan memakai Spatie permission (`hasRole` / `can`).
- Kursus:
  - Tambah CourseResource di Filament untuk manajemen course, enrollment, instructor assignment.
  - Tetap gunakan Inertia untuk halaman belajar (student experience).
- Inertia menu:
  - Cocokkan `sidebar-menu-config.ts` dengan keputusan role:
    - Writer: fokus CMS (Berita, Beasiswa, Job).
    - Editor: CMS + manajemen kursus (jika diizinkan).
    - Admin: menu lengkap backoffice (via Filament), plus akses ke dashboard operasional yang relevan.
    - Instructor: akses “Kursus Saya” dan monitoring peserta (Inertia).
    - Subscriber: portal pengguna (kelas, lamaran, profil).

### Fase 4 – Konsolidasi dan Pembersihan

- Setelah semua policy, Filament resource, dan sidebar memakai Spatie:
  - Audit seluruh kode yang masih menggunakan `users.role` langsung.
  - Ganti dengan call Spatie (`hasRole`, `hasPermissionTo`).
  - Setelah benar-benar bersih, hapus kolom `users.role`.
- Dokumentasi:
  - Perbarui dokumentasi menu dashboard per role agar mengacu ke matrix role/permission ini.
  - Jadikan file ini sebagai referensi arsitektur, sedangkan file `01._daftar_menu_dashboard_users.md` sebagai arsip diskusi dan catatan troubleshooting.

## 7. Dampak ke Menu Dashboard per Role (Ringkasan Konseptual)

- Admin:
  - Mengakses semua manajemen via Filament (CMS, E-Learning, Site Management, Master Data).
  - Melihat menu kursus dan backoffice lain sesuai resource Filament yang diaktifkan.
- Editor:
  - Mengelola konten CMS dan, jika disetujui, mengelola kursus dari sisi konfigurasi.
  - Tidak mengubah site settings.
- Writer:
  - Fokus ke konten CMS (News, Scholarship, Job).
  - Tidak memiliki menu Site Management dan Programs struktural.
- Instructor:
  - Mengakses “Kursus Saya” dan halaman monitoring di Inertia.
  - Tidak memiliki akses ke Site Management atau master data.
- Subscriber:
  - Mengakses portal (kelas, lamaran, profil) tanpa akses ke panel manajemen.

## 8. Cara Menggunakan Blueprint Ini

- Setiap kali akan mengubah menu dashboard:
  - Cek dulu role dan domain di matrix ini.
  - Pastikan penambahan menu selaras dengan permission yang dijalankan di backend (Spatie + policy).
- Setiap kali ada role baru:
  - Tambahkan ke roles Spatie.
  - Tentukan domain dan permission sesuai pola domain.entity.action.
  - Perbarui dokumentasi ini dan menu dashboard yang relevan.
