## Latar Belakang

Item 2 menetapkan kontrak resmi enum `status` `news`:

```sql
status = 'published'
AND published_at IS NOT NULL
AND published_at <= NOW()
```

Konsekuensi kontrak ini:

- Hanya **2 nilai literal** yang boleh ada di kolom `status`: **`draft`** & **`published`**.
- *"Terjadwal" (scheduled)* **bukan** nilai status terpisah — ia adalah **kondisi turunan** dari `status='published'` + `published_at` di masa depan.

Namun saat eksekusi Item 3 (standardisasi `video_urls`) selesai, audit menyeluruh pada lapisan input menemukan **tiga jalur input** yang **tidak konsisten** dengan kontrak Item 2 — semuanya berpotensi menulis nilai status yang menjadi *ghost* (tidak terambil oleh scope manapun di endpoint publik):

| Lapisan | Nilai diizinkan (sebelum) | Masalah |
|---------|---------------------------|---------|
| `app/Filament/Resources/News/Schemas/NewsForm.php` (Select) | `draft, review, published` | `review` tidak dikenali model/scope/policy/controller — admin yang memilih `review` akan menyimpan berita "ghost". |
| `app/Filament/Resources/News/Tables/NewsTable.php` (badge color + filter) | `draft, review, published` | Sama. Filter `review` tidak akan mendeteksi data "scheduled" yang sebenarnya butuh perhatian admin. |
| `app/Http/Requests/StoreNewsRequest.php` & `UpdateNewsRequest.php` | `in:draft,scheduled,published` | `scheduled` lolos validasi → bisa tersimpan literal di kolom — tidak akan tampil di publik (`scopePublished` cek `status='published'`) **dan** tidak akan terhitung di dashboard `News::scheduled()->count()` (scope itu juga cek `status='published'`). |

> Konsekuensi nyata: jika satu admin memakai Filament dan satu lagi memakai endpoint controller (mis. lewat `cms.news.create` route lama atau API), keduanya bisa menulis nilai yang *valid menurut layer masing-masing* tapi tidak nyambung ke kontrak Item 2.

### 2. `app/Filament/Resources/News/Tables/NewsTable.php`

**Badge `status`:** sebelumnya hanya menampilkan literal `draft|review|published`. Setelah perbaikan, badge tahu kondisi turunan:

```php
TextColumn::make('status')
    ->badge()
    ->formatStateUsing(function (string $state, $record): string {
        if ($state === 'published' && $record->published_at && $record->published_at->isFuture()) {
            return 'Terjadwal';
        }
        return ucfirst($state);
    })
    ->color(function (string $state, $record): string {
        if ($state === 'published' && $record->published_at && $record->published_at->isFuture()) {
            return 'warning';
        }
        return match ($state) {
            'draft' => 'gray',
            'published' => 'success',
            default => 'gray',
        };
    }),
```

> Hasil di UI admin: berita status=`published` + `published_at` masa depan tampil sebagai badge **"Terjadwal" (warning/oranye)** — admin langsung tahu berita itu belum tayang meskipun status literalnya `published`.

**Filter status:** sebelumnya 3 opsi literal (termasuk `review`). Diganti dengan **filter logis** 3 opsi yang sinkron kontrak:

```php
SelectFilter::make('status')
    ->label('Status')
    ->options([
        'draft' => 'Draft',
        'scheduled' => 'Terjadwal',
        'published' => 'Published',
    ])
    ->query(function ($query, array $data) {
        $value = $data['value'] ?? null;
        if ($value === 'draft') {
            return $query->where('status', 'draft');
        }
        if ($value === 'scheduled') {
            return $query
                ->where('status', 'published')
                ->where('published_at', '>', now());
        }
        if ($value === 'published') {
            return $query
                ->where('status', 'published')
                ->whereNotNull('published_at')
                ->where('published_at', '<=', now());
        }
        return $query;
    }),
```

> *Catatan teknis:* opsi `scheduled` & `published` di filter ini adalah **virtual** — tidak ditulis ke kolom `status`, hanya dipakai sebagai diskriminator query. Sinkron dengan `News::scopeScheduled` & `News::scopePublished`.

### 3. `app/Http/Requests/StoreNewsRequest.php` & `UpdateNewsRequest.php`

- Aturan `status` diubah: `in:draft,scheduled,published` → **`in:draft,published`**.
- Tambah `messages.status.in` Bahasa Indonesia.
- Tambah komentar PHPDoc mini yang merujuk kontrak `04._news_item_2.md` dan menyatakan bahwa "Terjadwal" adalah turunan, bukan nilai literal.

```php
// SESUDAH (kedua FormRequest)
'status' => 'required|in:draft,published',

// messages():
'status.in' => 'Status berita hanya boleh draft atau published',
```
