# 🔥 Penyebab Paling Umum dalam Kasus Seperti Ini

## 1️⃣ Database Server Lambat / Down

Kalau kamu pakai:

* Hosting shared
* MySQL container
* Docker
* VPS RAM kecil

Kadang MySQL overload → query pertama saja bisa 30 detik.

---

## 2️⃣ Tidak Ada Index di Kolom `key`

Karena kamu punya:

```php
TextColumn::make('label')->searchable()
TextColumn::make('key')->searchable()
```

Searchable di Filament = pakai `LIKE %keyword%`

Kalau kolom tidak di-index dan data ribuan → bisa lambat.

Cek di database:

```sql
SHOW INDEX FROM site_settings;
```

Kalau tidak ada index untuk `key`, tambahkan:

```sql
ALTER TABLE site_settings ADD INDEX idx_key (key);
```

---

## 3️⃣ Tabel Terkunci (Locking)

Kalau ada proses lain:

* migration jalan
* import data besar
* queue stuck
* backup jalan

Maka query bisa menunggu lock → 30 detik → timeout.

Cek:

```sql
SHOW PROCESSLIST;
```

Kalau ada status:

```
Waiting for table metadata lock
```

Itu penyebabnya.

---

## 4️⃣ Masalah Session Driver

Karena ini admin panel, setiap request pakai session.

Cek di `.env`:

```env
SESSION_DRIVER=
```

Kalau pakai:

```
database
```

Dan tabel `sessions` besar + tidak ada index → bisa lambat.

Coba sementara ubah ke:

```env
SESSION_DRIVER=file
```

Lalu test lagi.

# 🚀 Tes Paling Cepat Sekarang

Lakukan 3 hal ini:

### ✅ 1. Test Query Manual

Masuk tinker:

```bash
php artisan tinker
```

Lalu:

```php
App\Models\SiteSetting::count();
```

Kalau lama → DB bermasalah.

---

### ✅ 2. Test DB Connection

Buat route sementara:

```php
Route::get('/db-test', function () {
    return \DB::select('SELECT 1');
});
```

Kalau ini saja lama → DB issue.

---

### ✅ 3. Cek Jumlah Data

Berapa isi tabel:

```sql
SELECT COUNT(*) FROM site_settings;
```

Kalau cuma < 100 row tapi tetap 30 detik → pasti bukan table ini.
