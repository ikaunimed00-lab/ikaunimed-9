## 1. Akar Utama #1 – Kebocoran Kredensial Aktif di Repo (KRITIS)

### 1.1. Bukti

| File | Isi sensitif |
|------|--------------|
| `documentations/16._google_authentication/01._data_google_auth.md` | **Client ID** dan **Client Secret** Google OAuth (`GOCSPX-…`) plain-text |
| `documentations/16._google_authentication/02._file_json_google_auth.json` | File JSON OAuth lengkap dengan `client_secret`, `redirect_uris`, `javascript_origins` |
| `documentations/17._data_cpanel_hosting/01._data_cpanel_hosting.md` | IP server cPanel, user SSH (`elawepco`), document root absolut, path SSH key user |
| `old_env_backup.backup` (root) | Kemungkinan besar isi `.env` lama (DB password, APP_KEY, mail, dst.) – TIDAK di-cover oleh `.gitignore` |

### 1.2. Mengapa berbahaya

- **`.gitignore` hanya menutup** `.env`, `.env.backup`, `.env.production`. **Tidak** menutup `*.backup` generik, dokumentasi di folder `documentations/`, atau JSON kredensial.
- Status saat ini: file-file tersebut **muncul sebagai `??` (untracked)**, jadi memang belum pernah masuk commit. **Kabar baik.** Tapi mereka **tetap ada di working tree** dan akan tertambah seketika seseorang melakukan `git add .`.
- Client Secret Google itu **masih valid** (belum di-rotate). Jika repo pernah/akan di-push ke remote (GitHub, GitLab, dsb.) atau di-share, attacker bisa: ambil _Client ID + Secret_ → buat aplikasi peniruan yang valid → memancing user IKA UNIMED untuk login.
- Detail SSH cPanel + path key memberi roadmap konkret untuk attacker: cukup curi/tebak SSH key dan langsung punya akses root-folder server.

### 1.3. Rekomendasi Perbaikan

A. **Cegah kebocoran ke depan (defense-in-depth `.gitignore`):**

```gitignore
# Tambahan di .gitignore
*.backup
*.zip
*.tar.gz
old_env_backup*
documentations/16._google_authentication/*.json
documentations/16._google_authentication/01._data_google_auth.md
documentations/17._data_cpanel_hosting/*.md
```

B. **Pindahkan kredensial yang sudah ada keluar dari working tree:**

- Pindahkan isi `01._data_google_auth.md` dan `02._file_json_google_auth.json` ke **password manager** (Bitwarden, 1Password, KeePassXC, atau Google Cloud Console).
- Hapus dari working tree: `02._file_json_google_auth.json`, `01._data_google_auth.md` (versi yang bocor).
- Ganti dengan placeholder `01._data_google_auth.md` yang hanya menjelaskan _"kredensial disimpan di password manager X, redirect URI: …, scopes: …"_ tanpa secret nyata.

C. **Rotasi kredensial yang sudah bocor (sangat disarankan):**

- Google Cloud Console → OAuth Clients → reset client secret untuk client `591354408958-…`.
- Server cPanel → ubah password user `elawepco`, regenerate SSH key untuk laptop Anda.
- Database hosting → ubah password DB; update `.env` di server.

D. **Hapus `old_env_backup.backup`** – simpan offline (bukan di folder repo).

> Rotasi kredensial (langkah C) **harus dilakukan oleh Anda** karena melibatkan akun pihak ketiga; saya hanya bisa membantu langkah A, B, D.

## 2. Akar Utama #2 – `public/build/` Di-track di Git + Artefak Deploy di Root (TINGGI)

### 2.1. Bukti

- `git ls-files public/build` mengembalikan **112 file** (di-track aktif).
- `git status --porcelain public/build` menunjukkan **228 perubahan** (gabungan `D` deleted + `??` baru) – semua karena Vite menghasilkan filename ber-hash baru tiap `npm run build`.
- Artefak build di root yang bercampur dengan source: `assets.zip`, `build.zip`, `source.zip`, `build.tar.gz`.
- 30+ skrip ad-hoc deploy/fix di root: `fix_*.sh`, `fix_*.ps1`, `deploy_*.ps1`, `upload_*.ps1`, `get_google_env*.ps1`, `verify_*.ps1`, `cleanup_repos.sh`, dll.
- Folder `deploy_stage/` di repo (staging area lokal yang bocor ke working tree).

### 2.2. Mengapa Ini Sumber Utama "Rasa Tidak Selesai"

- Setiap kali Anda `npm run build` → 50+ file lama "deleted", 50+ file baru "added" di Git status.
- Akibat: `git status` Anda **tidak akan pernah bersih** selama `public/build/` di-track.
- Diff jadi tidak bisa dibaca – setiap PR review penuh dengan _binary blob diff_ dari Vite chunks.
- Ini juga yang memaksa Anda menggunakan pola **build lokal → zip → SCP manual** (lihat `DEPLOYMENT_GUIDE.md`) – sehingga lahir 30+ skrip ad-hoc di root sebagai band-aid.

### 2.3. Rekomendasi Perbaikan

A. **Untrack `public/build/` dari Git** dan tambahkan ke `.gitignore`:

```gitignore
/public/build
```

```bash
# Hanya untag dari git, file tetap ada di disk:
git rm -r --cached public/build
```

B. **Pindahkan artefak deploy dari root** ke folder `deploy/` (atau hapus jika sudah tidak relevan):

```text
deploy/                     # opsional, di-gitignore
├── scripts/                # fix_*.sh, deploy_*.ps1, upload_*.ps1
├── archives/               # assets.zip, source.zip, build.tar.gz, dll.
└── stage/                  # bekas deploy_stage/
```

C. **Tambahkan ke `.gitignore`:**

```gitignore
/deploy
/deploy_stage
*.zip
*.tar.gz
*.backup
debug_local_home.html
public/index_production.php   # biarkan di server saja
```

D. **Strategi build yang sehat untuk shared hosting cPanel:**

- Tetap _build di lokal_ (server tidak punya Node), tetapi **bukan** lewat zip → SCP folder satu-satu.
- Pakai pola **rsync** atau script SCP **tunggal** dengan hanya 2 langkah: `npm run build` lalu `rsync -avz --delete public/build/ user@host:.../public/build/`.
- Atau, jika tetap ingin via zip: cukup 1 skrip `deploy.ps1` yang baik, **letakkan di `deploy/` (di-gitignore)**, bukan di root.

> Setelah eksekusi A+B+C, `git status` akan langsung berkurang dari 407 → ~50 perubahan yang benar-benar relevan.

## 3. Akar Utama #3 – 407 Perubahan Tidak Atomik (TINGGI)

### 3.1. Bukti

- Total `git status --porcelain`: **407 file**.
- Komposisi (di luar `public/build/` dan `deploy_stage/`):
  - **84 file modified (`M`)** – mencampur Filament Resources, Controllers, Providers, Models, Policies, frontend pages, config.
  - **12 migrasi baru** di `database/migrations/` (Coupon, CouponUsage, Quiz, QuizAttempt, Shipment, course_id ke products, dll.) – semuanya `??` (untracked).
  - **Banyak file baru fitur besar**: Coupon (Resource, Pages, Service, Repository), Quiz, QuizAttempt, Shipment, NewsObserver, CourseLearningService, CouponService, TripayPaymentSettled event + listener, SuperAdminSeeder, ShopLmsDemoSeeder.

- Commit terakhir: `bcfb83c Add feature tests that hit CourseController HTTP endpoints.` – setelah itu **tidak ada commit lagi** padahal kode sudah berkembang jauh.

### 3.2. Mengapa Ini Berbahaya

- **Risiko deploy schema:** 12 migrasi baru. Jika di-deploy dengan urutan timestamp yang salah, atau ada migrasi yang lupa di-upload, schema database akan _setengah jadi_ – sulit di-rollback karena tidak ada commit checkpoint.
- **Tidak ada "checkpoint hijau":** Jika fitur Coupon ternyata bermasalah di production, tidak ada commit terpisah untuk di-revert. Anda harus melakukan _surgery manual_ pada working tree.
- **Code review tidak mungkin:** 84 file modified bercampur tanpa konteks per-fitur.
- **Inilah penyebab "rasa berputar":** 30+ fix script di root muncul sebagai _patch_ untuk masalah-masalah yang sebenarnya bisa dicegah jika tiap fitur punya commit + migrasi yang konsisten.
