## 05. Role → Permission → Scope Flow

### 05.1 Diagram Alur

```text
[Role (Spatie Role)]
        │
        ▼
[Permission Set]
  (RolesAndPermissionsSeeder)
        │
        ▼
[Menu + Actions]
  - Filament (canViewAny, canCreate, dll.)
  - Inertia (SIDEBAR_MENU, tombol aksi)
        │
        ▼
[Scope Data]
  - OrganizationScopeService (organization_id)
  - isCentralAdmin() + organization_id + parent_id
```

Ringkasnya:

- Role = label tinggi (`super_admin`, `admin`, `editor`, `writer`, `learner`, `instructor`, `lms_moderator`, `subscriber`).
- Permission = kemampuan granular (`cms.*`, `site.*`, `master.*`, `elearning.*`, dll).
- Menu + Actions:
  - Filament: kontrol akses via `canViewAny`, `canCreate`, `canEdit`, `canDelete`.
  - Inertia: kontrol menu via `SIDEBAR_MENU` + filter permission.
- Scope Data:
  - `OrganizationScopeService` membatasi data per organisasi.
  - `isCentralAdmin()` + kombinasi `organization_id` / `parent_id` mengatur hirarki PP/DPW/DPC.

### 05.1.1 Tabel Ringkas Role → Permission → Scope → UI

| Role                              | Permission kunci                                              | Scope Data                                                                                           | UI Layer                                      |
|-----------------------------------|---------------------------------------------------------------|------------------------------------------------------------------------------------------------------|----------------------------------------------|
| super_admin                       | Semua `master.*`, `cms.*`, `site.*`, `elearning.*`           | Global (tidak dibatasi organisasi)                                                                   | Filament (semua resource governance)         |
| Admin Pusat (`admin`, org null)   | `master.organizations.manage`, `master.users.manage`, `cms.*`| Global: `OrganizationScopeService` tidak mem‑filter; `OrganizationResource` tidak dibatasi           | Filament: News, Users, Organizations, dll    |
| Admin Wilayah (admin + org_id)    | `master.organizations.manage`, `cms.*`                       | - `OrganizationScopeService`: hanya baris dengan `organization_id = user.organization_id` (News, User, dst)  <br> - `OrganizationResource`: hanya `id = organization_id` atau `parent_id = organization_id` | Filament: NewsResource, UserResource, OrganizationResource |
| Editor/Writer terikat organisasi  | Subset `cms.*` sesuai seeder                                 | `OrganizationScopeService`: jika punya `organization_id` → hanya data organisasinya; jika tidak → kosong | Filament: NewsResource                       |
| Subscriber / Learner              | `portal.profile.*`, `portal.dashboard.*`, `elearning.participant.*` | Tidak lewat `OrganizationScopeService`; scope diatur oleh middleware (`EnsureProfileCompleted`) dan policy course/enrollment | Inertia: dashboard subscriber & LMS          |

### 05.2 Skenario: Admin Pusat vs Admin DPW vs Admin DPC

Asumsi:

- Admin Pusat:
  - `role = admin`, `organization_id = null`
  - `isCentralAdmin() === true`
- Admin DPW/DPC:
  - `role = admin`, `organization_id != null`
  - `isCentralAdmin() === false`, `hasOrganizationScope() === true`

#### a) Mengelola Berita (News)

- Permission:
  - Admin pusat, DPW, DPC sama‑sama punya `cms.news.*` sesuai seeder.
- Scope (Filament `NewsResource` + `OrganizationScopeService`):
  - Admin pusat: melihat semua berita (tanpa filter organisasi).
  - Admin DPW/DPC: hanya melihat berita dengan `organization_id` sesuai organisasinya.
- Inertia:
  - Saat membuat berita organisasi, `organization_id` otomatis dikunci ke organisasi user (kecuali admin pusat).

#### b) Mengelola User (UserResource)

- Permission:
  - Akses menu User Management → `master.users.manage`.
- Scope (Filament `UserResource` + `OrganizationScopeService`):
  - Admin pusat:
    - Melihat semua user.
    - Bisa create/edit/delete (sesuai aturan di resource).
  - Admin DPW/DPC:
    - Hanya melihat user yang `organization_id` sama.
    - Hanya bisa edit user dalam organisasinya dan bukan sesama admin.

#### c) Mengelola Organisasi (OrganizationResource)

- Permission:
  - Lihat daftar organisasi → `master.organizations.manage`.
  - Create/Edit/Delete:
    - `isCentralAdmin()` **atau** permission `master.organizations.manage_hierarchy`.
- Scope & Hirarki:
  - Admin pusat:
    - Mengelola seluruh hirarki (PP, DPW, DPC) via Filament.
  - Admin DPW/DPC:
    - Bisa melihat sesuai kebutuhan, tapi tidak bisa mengubah struktur
      kecuali diberi permission `master.organizations.manage_hierarchy`.
  - Controller Inertia (OrganizationController, OrganizationMemberController)
    menambah batasan:
    - Admin non‑pusat hanya boleh mengelola organisasi sendiri dan child langsungnya.

Bukan "LMS", agar tidak membingungkan dengan Inertia LMS.

---

# 🔗 5️⃣ LMS - APPLICATION ENTRY POINT

Di bagian paling bawah navigation:

```
LMS Application
- Buka Dashboard LMS
- Kursus Saya
- Dashboard LMS (Moderator)
```

Semua ini berupa `NavigationItem` yang menjadi pintu masuk ke LMS (Inertia),
dengan URL berbasis permission:

```text
- Buka Dashboard LMS
  - Jika punya permission learner (`elearning.participant.enroll`)
    → route('dashboard.elearning.learner.courses.index')
  - Jika tidak learner tapi punya permission moderator (`elearning.course.view_any`)
    → route('dashboard.elearning.moderator.courses.index')
  - Jika tidak keduanya tapi punya permission instruktur
    (`elearning.course.view` / `elearning.course.view_own`)
    → route('dashboard.courses.index')
  - Fallback → route('dashboard')

- Kursus Saya (LMS)
  → route('dashboard.elearning.learner.courses.index')

- Dashboard LMS (Moderator)
  → route('dashboard.elearning.moderator.courses.index')
```

Tujuannya:
Filament tetap menjadi pintu masuk ke Inertia,
sementara pemilihan halaman landing LMS ditentukan oleh permission LMS (`elearning.*`).

## ✅ 5️⃣ Tambahkan Entry Point ke Inertia

Masih di `AdminPanelProvider`:

```php
use Filament\Navigation\NavigationItem;

->navigationItems([
    NavigationItem::make('Buka Dashboard LMS')
        ->group('LMS Application')
        ->url(function () {
            $user = Auth::user();

            if (! $user) {
                return route('dashboard');
            }

            if ($user->can('elearning.participant.enroll')) {
                return route('dashboard.elearning.learner.courses.index');
            }

            if ($user->can('elearning.course.view_any')) {
                return route('dashboard.elearning.moderator.courses.index');
            }

            if ($user->can('elearning.course.view') || $user->can('elearning.course.view_own')) {
                return route('dashboard.courses.index');
            }

            return route('dashboard');
        })
        ->icon('heroicon-o-academic-cap'),

    NavigationItem::make('Kursus Saya (LMS)')
        ->group('LMS Application')
        ->url(fn () => route('dashboard.elearning.learner.courses.index'))
        ->icon('heroicon-o-academic-cap'),

    NavigationItem::make('Dashboard LMS (Moderator)')
        ->group('LMS Application')
        ->url(fn () => route('dashboard.elearning.moderator.courses.index'))
        ->icon('heroicon-o-academic-cap'),
])
```

Tambahkan condition `visible(...)` per item sesuai permission:

```php
->visible(fn () => Auth::user()?->hasAnyPermission([
    'elearning.participant.enroll',
    'elearning.course.view',
    'elearning.course.view_own',
    'elearning.course.view_any',
    'elearning.course.create',
]) ?? false)
