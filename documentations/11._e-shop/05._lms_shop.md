## 05. LMS × E-Shop – Ringkasan Progres Implementasi

Dokumen ini merangkum progres integrasi antara modul E-Shop dan LMS, termasuk:
- pemetaan produk digital ke course,
- alur enrollment otomatis dari pembayaran,
- membership premium dan diskon,
- sistem kupon,
- observability/admin tooling di Filament,
- serta aspek ketahanan (hardening) di sekitar payment dan webhook.

Struktur ini dimaksudkan sebagai _living document_ yang dapat diperbarui saat fitur berkembang.

---

## 1. Produk Digital Shop ↔ Course LMS

### 1.1. Model & skema data

- `products`:
  - Menyimpan informasi produk Shop (fisik, digital, jasa).
  - Field penting:
    - `type` – enum string: `physical`, `digital`, `service`.
    - `course_id` – relasi ke `courses.id` (hanya relevan jika `type = digital`).
  - Invariant:
    - Jika `type = digital` maka `course_id` harus terisi dan mengarah ke course LMS yang valid.
    - Jika `type != digital` maka `course_id` boleh null.

- `courses`:
  - Menyimpan course LMS.
  - Memiliki flag:
    - `is_paid` – apakah course berbayar.
    - `requires_premium` – apakah hanya boleh diakses member premium.

### 1.2. Filament: ProductResource

File: `app/Filament/Resources/Shop/ProductResource.php`

- Field utama:
  - `type` – pilih jenis produk (`physical`, `digital`, `service`).
  - `course_id` – Select relasi ke `Course`:
    - `required` dan `visible` jika `type = digital`.
    - `hidden` jika `type != digital`.
  - `membership_role` – dipakai untuk produk membership (lihat bagian membership).

- Validasi & UX:
  - Saat membuat produk digital, user dipaksa memilih `course_id` yang valid.
  - Ada invariant di model + validasi di Filament untuk mencegah produk digital tanpa course.

### 1.3. Checkout → Enrollment LMS

File utama: `app/Http/Controllers/ShopController.php` (metode `processCheckout`)

Alur tinggi:

1. User menyelesaikan checkout dengan produk (fisik dan/atau digital).
2. Order dan Payment dibuat dalam satu transaksi database.
3. Untuk produk digital:
   - Setelah Payment berstatus `paid`:
     - Sistem mencari `product.course_id`.
     - Mengambil `Course` dengan status `published`.
     - Membuat atau memperbarui `Enrollment`:
       - `user_id` = pembeli.
       - `course_id` = course terkait produk.
       - `status` = `active`.
       - `started_at` diisi jika sebelumnya null.
4. Proses ini terjadi baik via:
   - callback Tripay (webhook),
   - maupun manual confirm di sisi admin (PaymentResource → action `confirmPayment`).

### 1.4. Enrollments & akses learner

- Model `Enrollment`:
  - Menyimpan hubungan user–course.
  - Dipakai untuk menentukan course mana yang muncul di dashboard learner dan progress belajar.

- UI learner:
  - Tombol **“Lanjutkan Belajar”**:
    - Ada di halaman Course Show.
    - Jika user sudah enroll:
      - Tombol diarahkan ke lesson berikutnya yang belum selesai.
      - Ada perbedaan view antara visitor, enrolled learner, dan premium-only course.

## 2. Membership Premium dan Diskon E-Shop

### 2.1. Produk membership premium

- Ada jenis produk `service` yang merepresentasikan membership premium.
- Field `membership_role` di `products`:
  - Biasanya diisi `premium_member`.
  - Saat payment sukses untuk produk membership:
    - Role `premium_member` diberikan ke user (melalui alur webhook/konfirmasi payment).

### 2.2. Pembatasan akses course premium

- Course LMS memiliki flag `requires_premium`.
- Kebijakan:
  - Jika `requires_premium = true`, hanya user dengan role `premium_member` yang boleh mengakses/enroll.
  - Ini dikombinasikan dengan status enrollment untuk menentukan akses penuh ke materi.

### 2.3. Diskon otomatis untuk member premium

Tujuan: Member premium dapat diskon otomatis untuk produk fisik tertentu di E-Shop.

Implementasi di `ShopController@processCheckout`:

- Sumber konfigurasi:
  - `SiteSetting::getValue('shop_premium_member_discount_rate', 0.1)`
    - Menyimpan persentase diskon (float), default 0.1 (10%) sebagai fallback kompatibilitas.
  - `SiteSetting::getValue('shop_premium_member_discount_category_slugs', null)`
    - Menyimpan array slug kategori produk yang berhak dapat diskon.

- Aturan diskon:
  - Hanya untuk user dengan role `premium_member`.
  - Hanya untuk produk dengan `type = physical`.
  - Jika `shop_premium_member_discount_category_slugs`:
    - null / kosong → semua produk fisik dapat diskon.
    - terisi array slug → hanya produk fisik dengan kategori yang slug-nya ada di list tersebut.

- Perhitungan:
  - `physicalSubtotal` = total harga produk fisik yang memenuhi kategori diskon.
  - `discount = floor(physicalSubtotal * discountRate)` (dibulatkan ke bawah ke integer).

Sinkronisasi frontend–backend:

- Frontend cart/checkout menampilkan diskon dengan aturan yang sama agar angka di UI dan backend konsisten.
- Bila SiteSetting berubah, diskon otomatis ikut menyesuaikan.

## 3. Sistem Kupon (Coupon) di Shop

### 3.1. Skema database & model

- Tabel `coupons`:
  - Field penting:
    - `code` – string unik, disimpan uppercase.
    - `type` – `fixed` atau `percentage`.
    - `value`:
      - Jika `fixed`: nilai dalam rupiah.
      - Jika `percentage`: float 0–1 (misal 0.2 = 20%).
    - `max_discount` – batas maksimum nominal diskon untuk tipe persentase (opsional).
    - `usage_limit` – batas jumlah penggunaan (opsional).
    - `used_count` – counter total penggunaan (untuk statistik/limit).
    - `starts_at`, `expires_at` – periode berlakunya kupon (opsional).
    - `status` – `active` / `inactive`.

- Model `Coupon`:
  - `$fillable` mencakup field di atas.
  - `$casts`:
    - `value`, `max_discount` → `decimal:2`.
    - `starts_at`, `expires_at` → `datetime`.
  - Relasi:
    - `usages()` → hasMany ke `CouponUsage`.

- Tabel & model `coupon_usages`:
  - Menyimpan histori penggunaan kupon per order:
    - `coupon_id`
    - `order_id`
    - `user_id`
    - `used_at`
  - Model `CouponUsage` memiliki relasi:
    - `coupon()`, `order()`, `user()`.

- Relasi di `Order`:
  - `couponUsage(): HasOne` – satu order maksimal satu kupon.

### 3.2. Alur penggunaan kupon di checkout

Lokasi utama: `ShopController@processCheckout`

- Input:
  - Field tambahan request: `coupon_code` (nullable, max 50).
  - Frontend Checkout menambahkan input kode kupon dan mengirim ke backend.

- Validasi kupon:
  - `code` dicari case-insensitive (dibandingkan sebagai uppercase).
  - Kriteria kupon valid:
    - `status = active`.
    - `starts_at` <= sekarang (atau null).
    - `expires_at` >= sekarang (atau null).
    - Jika `usage_limit` di-set:
      - `used_count` < `usage_limit`.

- Perhitungan diskon kupon:
  - Basis perhitungan di atas subtotal yang relevan (setelah diskon membership premium diterapkan bila ada).
  - Tipe `fixed`:
    - Diskon = min(nilai fixed, total yang tersisa).
  - Tipe `percentage`:
    - Diskon = `total * value`.
    - Jika `max_discount` terisi:
      - Diskon dibatasi maksimum `max_discount`.

- Pencatatan penggunaan:
  - Dalam transaksi database yang sama dengan pembuatan Order dan Payment:
    - Dibuat record `CouponUsage` yang menghubungkan order, user, dan kupon.
    - `used_count` pada `coupons` di-increment.

- Urutan aplikasi diskon:
  1. Hitung total cart.
  2. Terapkan diskon membership premium (jika ada dan memenuhi syarat).
  3. Terapkan diskon kupon di atas nilai setelah diskon membership.

### 3.3. Filament: CouponResource (CMS)

File: `app/Filament/Resources/Shop/CouponResource.php`

- Hak akses:
  - Bisa diakses oleh:
    - `super_admin`, atau
    - user dengan permission `shop.coupon.manage` (diupdate dari `shop.settings.manage`).

- Form:
  - `code`:
    - Required, unique, max length 50.
    - Di-normalisasi ke uppercase pada onBlur.
  - `type`:
    - Pilihan `fixed` / `percentage`.
  - `value`:
    - Numeric; untuk persentase diisi 0–1.
  - `max_discount`:
    - Numeric opsional; batas maksimal rupiah untuk tipe persentase.
  - `usage_limit`:
    - Numeric opsional; jika null berarti unlimited.
  - `starts_at`, `expires_at`:
    - DateTimePicker, opsional.
  - `status`:
    - `active` / `inactive`.

- Tabel:
  - Kolom:
    - `code`, `type` (badge), `value` (diformat rupiah atau persentase).
    - `usage_summary`:
      - Jika `usage_limit` null → `used_count x` (misal `3x`).
      - Jika ada limit → `used_count / usage_limit x`.
    - `status` (badge warna).
    - `starts_at`, `expires_at`, `created_at`.
  - Filter:
    - Berdasarkan `status`.
  - Aksi:
    - Create, Edit, Delete, Bulk delete.

### 3.4. Observability kupon di Payment & Order

- `Order`:
  - Relasi `couponUsage` dimuat di `getEloquentQuery()`:
    - `->with(['user', 'organization', 'shipment', 'couponUsage.coupon'])`.
  - Infolist **Ringkasan Order** menampilkan:
    - `Kode Kupon`, `Tipe Kupon`, `Nilai Kupon` (jika ada).

- `Payment`:
  - Query default:
    - `->with(['order.items', 'order.couponUsage.coupon', 'user', 'logs'])`.
  - Tabel:
    - Kolom `Kupon` yang mengambil `order.couponUsage.coupon.code` dengan placeholder `-`.
  - Infolist **Ringkasan Payment**:
    - Menampilkan `Kode Kupon`, `Tipe Kupon`, dan `Nilai Kupon`.

## 4. Statistik & Health untuk LMS berbasis Payment

Walaupun belum ada resource statistik khusus yang dirancang hanya untuk kupon, PaymentResource sudah diposisikan sebagai “sumber kebenaran” untuk revenue LMS dan donasi.

### 4.1. Filter kupon untuk analisis revenue

Di `PaymentResource` (tabel), terdapat beberapa filter:

- `status` – status payment (`pending`, `paid`, `expired`, `failed`).
- `provider` – misalnya `tripay`.
- `created_at_range`, `paid_at_range` – filter rentang tanggal.
- `has_coupon` – filter sederhana untuk payment yang memiliki kupon.
- `Filter Kupon (Statistik LMS)`:
  - Opsinya:
    - `Hanya payment dengan kupon` – hanya transaksi yang memiliki `order.couponUsage`.
    - `Hanya payment tanpa kupon` – kebalikannya.
  - Implementasi:
    - Menggunakan `whereHas('order.couponUsage')` dan `whereDoesntHave('order.couponUsage')`.

Dengan kombinasi ini, di tabel Payment:

- Kolom `amount` sudah memiliki summarizer (Sum) → total otomatis dihitung untuk subset yang sedang difilter.
- Secara praktis Anda bisa mendapatkan:
  - Total revenue transaksi dengan kupon vs tanpa kupon untuk periode tertentu.
  - Menyaring hanya provider tertentu (misal Tripay) atau hanya status `paid`.

### 4.2. Health & debugging payment + LMS

Masih di `PaymentResource`:

- Kolom `order_summary`:
  - Menampilkan ringkasan produk yang dibeli pada order.
- Section `Payment Logs` di infolist:
  - Menampilkan log per-event (`event`, `status_code`, `payload`) untuk debugging webhook Tripay maupun manual confirm.
- Filter khusus:
  - `needs_investigation`:
    - Payment `pending` tetapi sudah ada log → indikasi masalah yang perlu dilihat.
  - `webhook_errors`:
    - Payment yang memiliki log dengan `status_code >= 400`.

## 5. Pembaruan UI & Integrasi Akhir (Terbaru)

### 5.1. Integrasi "Beli Kelas" ke Keranjang
- Halaman Course Show (`resources/js/Pages/Course/Show.tsx`) kini memiliki tombol "Beli Kelas" untuk course berbayar.
- Aksi tombol:
  - Melakukan POST ke route `shop.cart.add` dengan slug produk yang terhubung ke course.
  - Mengarahkan user ke halaman keranjang belanja (Cart).

### 5.2. Form Kupon di Checkout
- Halaman Checkout (`resources/js/Pages/Shop/Checkout.tsx`) telah diperbarui dengan fitur validasi kupon interaktif.
- Fitur:
  - Input kode kupon dengan tombol "Cek".
  - Validasi AJAX tanpa reload halaman (via endpoint `shop.checkout.check-coupon`).
  - Menampilkan pesan sukses/error dan nominal diskon secara real-time.
  - Diskon kupon dikalkulasi setelah diskon membership (jika ada) dan mengurangi total bayar.

### 5.3. Endpoint Validasi Kupon
- Route: `POST /shop/checkout/check-coupon`
- Controller: `ShopController@checkCoupon`
- Return: JSON `{ valid, message, discount, code }`.
- Logika:
  - Memvalidasi kode, status, tanggal berlaku, dan kuota.
  - Menghitung estimasi diskon berdasarkan isi keranjang saat ini.
