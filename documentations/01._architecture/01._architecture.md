# IKA UNIMED Portal – Architecture Documentation

Status: Adopted  
Last Reviewed: February 2026  

---

# 1. Architecture Philosophy

This project follows a **Hybrid Architecture Approach**:

- **Inertia + React** for public-facing and alumni-facing experiences.
- **Filament** for internal administration and moderation.
- Clear separation of responsibilities to avoid UI coupling.

Core Principle:

> The best tool for the job — UX for users, efficiency for administrators.

---

# 2. Technology Stack

## Backend

- Laravel 12.0
- API Resources (JsonResource for standardized responses)
- Eager Loading on critical queries
- Cache Driver: File (Redis-ready)
- MySQL Database

Backend Responsibilities:
- Business logic
- Data integrity
- Authorization & policies
- API standardization
- Shared domain services

---

## Frontend (Public & Alumni)

- Inertia.js (React Adapter v2.1.4)
- React v19.2.0
- Tailwind CSS v4.0.0
- Vite (ESM-based bundler)

Frontend Responsibilities:
- Public pages (News, Alumni, Jobs, etc.)
- Alumni dashboard (self-service features)
- Interactive UX flows (legalization, submissions, profile management)
- Brand-driven UI experience

---

## Admin (Internal Only)

- Filament v3
- Livewire v3
- Alpine.js (Admin-only runtime)

Admin Responsibilities:
- Content management (News, Pages, Organization)
- User management
- Moderation workflows
- Database utilities
- Internal reporting

Admin panel runs exclusively under:

/admin

# 4. Domain Separation Rules

## Access & Boundary Rules

- Filament is strictly for internal staff:
  - Admin
  - Editor
  - Writer

- Inertia Dashboard is strictly for:
  - Alumni
  - Subscribers
  - Public users

- No shared UI components between:
  - Filament
  - Inertia

- Shared logic must live in:
  - Models
  - Services
  - Policies
  - API Resources

---

# 5. Hybrid Domain Model

Some domains have dual interfaces:

Example: Job Vacancy / Scholarship / Legalization

User Side (Inertia):
- Submission
- Tracking
- Self-service management

Admin Side (Filament):
- Moderation
- Approval workflow
- Status updates
- Data verification

Single source of truth:
- Same database models
- Same API Resources
- Same authorization policies

---

# 6. Design Constraints

- Public performance must remain SPA-fast.
- Admin optimization prioritizes productivity over animation.
- Livewire is NOT used in public-facing UI.
- React is NOT used inside the Filament admin panel.

---

# 7. Long-Term Scalability

This architecture allows:

- Future mobile API expansion
- Redis cache activation without refactor
- Horizontal scaling
- Clear onboarding for new developers
