# 🏗 2️⃣ Opsi A vs Opsi B (Ini Kunci Besar)

## Opsi A – Settings (key-value)

Cocok untuk:

* teks sederhana
* footer
* social links
* kontak

Tidak cocok untuk:

* carousel multi-slide
* CTA dengan ordering
* dynamic section

Jadi benar, ini tidak ideal untuk homepage kompleks.

---

## Opsi B – Tabel Terpisah per Section

Lebih clean, lebih scalable.

Tapi saya tidak sepenuhnya setuju jika setiap section jadi tabel terpisah tanpa strategi.

Karena nanti bisa jadi:

* hero_slides
* cta_cards
* homepage_videos
* homepage_features
* homepage_packages
* homepage_text_blocks
* homepage_layout_settings

Itu bisa membengkak dan sulit maintain.

---

# 🧠 3️⃣ Opsi C (Yang Lebih Scalable & Enterprise)

Saya sarankan pendekatan hybrid terstruktur:

Buat satu tabel utama:

```
homepage_sections
```

Struktur:

| id | type | data (json) | order | is_active |

Contoh:

type = hero
data = { title, subtitle, image, link }

type = cta
data = { title, icon, link }

type = video
data = { youtube_url, description }

Keuntungan:

* Flexible
* Tidak perlu migrasi setiap kali tambah section
* Bisa reorder
* Bisa toggle aktif/nonaktif
* Bisa dipakai untuk future landing page

Ini pattern modern CMS (block-based architecture).

Mirip:

* WordPress Gutenberg
* Payload CMS
* Headless CMS

# 🧭 5️⃣ Scope – Ini Pertanyaan Paling Penting

Trae.ai bertanya:

> Global atau DPW/DPC juga punya landing page?

Ini bukan pertanyaan kecil.

Kalau ke depan ada:

* Homepage Nasional
* Homepage DPW
* Homepage DPC

Maka struktur sekarang harus siap multi-tenant.

Kalau tidak, nanti migrasi ulang.

Saya sarankan:

Sekarang global dulu.

Tapi struktur database sudah siap untuk:

```
scope_type (global, dpw, dpc)
scope_id
```

Walaupun belum dipakai.

Future-proof.

---

# 🎛 6️⃣ Apakah Editor Bisa Reorder?

Kalau homepage adalah marketing page:

YA. Reorder itu penting.

Minimal:

* reorder hero slides
* reorder CTA
* reorder feature list

Filament sudah support:

```
->reorderable()
```

Jadi ini mudah.

# 📁 7️⃣ Media Handling

Gunakan:

```
FileUpload::make('image')
    ->image()
    ->directory('homepage')
```

Tambahkan:

* maxSize (misal 2MB)
* aspect ratio guideline

Dan penting:

Simpan optimized version (jangan raw 5MB upload).

# 🧱 8️⃣ Arsitektur Inertia Side

Di React (Index.tsx), nanti:

Homepage akan menerima props:

```ts
homepage: {
    hero: [],
    cta: [],
    sections: []
}
```

Jangan biarkan React query database sendiri.

Semua lewat Controller:

```
HomepageController@index
```

Ini menjaga separation of concern.

---

# 🔥 9️⃣ Hal Paling Penting (Yang Jarang Dibahas)

Jangan buat homepage 100% editable tanpa batasan desain.

Editor sebaiknya:

Bisa mengubah:

* teks
* gambar
* link
* urutan

Tapi tidak bisa:

* mengubah layout grid
* mengubah warna
* menghapus struktur fundamental

Karena kalau terlalu bebas:
Homepage bisa rusak secara visual.

Sebelum kita masuk blueprint detail:

3. Apakah DPW/DPC akan punya homepage sendiri di masa depan?
4. Apakah Anda ingin homepage bisa “disable section” tanpa delete?
