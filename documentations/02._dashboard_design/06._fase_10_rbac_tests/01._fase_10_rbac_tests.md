## 14. Fase 10: RBAC Dashboard Tests (Stabilisasi `/dashboard`)

### 14.1. Tujuan Fase 10

- Mengunci perilaku redirect `/dashboard` untuk role utama:
  - `admin`
  - `editor`
  - `writer`
  - `subscriber`
- Menjadikan alur RBAC yang sebelumnya hanya “terlihat benar” menjadi **teruji** melalui test otomatis.

Fokus Fase 10 dibatasi pada **alur dashboard utama**, bukan seluruh permission matrix Filament/CMS (itu bisa menjadi ekspansi fase berikutnya jika dibutuhkan).

---

### 14.2. Kondisi Sebelum Fase 10

- RBAC berbasis Spatie sudah berjalan (Fase 1–9):
  - Seeder roles & permissions tersentral di `RolesAndPermissionsSeeder`.
  - Policy dan controller sudah memakai `can('...')` / `hasRole(...)`.
  - Redirect dashboard sudah memakai:
    - `hasAnyRole(['admin', 'editor', 'writer'])` → `/admin`
    - `hasRole('subscriber')` → `dashboard.subscriber`
- Sidebar dashboard (Admin/Editor/Writer/Subscriber) sudah permission-aware (Fase 9).
- Namun:
  - Belum ada test otomatis yang secara eksplisit menguji:
    - Perilaku redirect `/dashboard` per role.
    - Kewajiban melengkapi profil untuk `subscriber`.
  - Test lama `DashboardTest` masih mengasumsikan `/dashboard` merender halaman langsung (`assertOk()`), bukan redirect.

---

### 14.3. Desain Perilaku yang Diuji

Route sumber kebenaran:

- File: `routes/web.php`
- Bagian:
  - `Route::get('/dashboard', function () { ... })->name('dashboard');`

Perilaku yang diharapkan:

1. Guest:
   - Akses `route('dashboard')`:
     - Redirect ke `route('login')`.
2. Admin/Editor/Writer:
   - Setelah login dan mengakses `route('dashboard')`:
     - Redirect ke `/admin`.
3. Subscriber dengan profil **belum lengkap**:
   - Akses `route('dashboard')`:
     - Redirect ke `route('profile.edit')`.
4. Subscriber dengan profil **sudah lengkap** (field wajib terisi):
   - Akses `route('dashboard')`:
     - Redirect ke `route('dashboard.subscriber')`.

---

### 14.4. Perubahan di Test yang Ada

File: `tests/Feature/DashboardTest.php`

Sebelum:

- Test kedua mengasumsikan:
  - User autentikasi, Akses `route('dashboard')` → `assertOk()`.
- Ini sudah tidak sesuai dengan flow baru yang selalu melakukan redirect.

Sesudah Fase 10:

- Test `authenticated users can visit the dashboard` diperbarui menjadi:
  - User login (tanpa role spesifik):
    - Secara praktik diperlakukan seperti subscriber yang profilnya belum lengkap.
  - Ekspektasi:
    - `assertRedirect(route('profile.edit'));`

Dengan ini, test bawaan tetap dipakai, tetapi mengikuti arsitektur redirect terbaru.

---

### 14.5. Penambahan File Test Baru: `RbacDashboardTest`

File: `tests/Feature/RbacDashboardTest.php`

Karakteristik:

- Menggunakan Pest, sama seperti test lain di project.
- Menjalankan seeder roles & permissions setiap test:

  ```php
  use Database\Seeders\RolesAndPermissionsSeeder;

  beforeEach(function () {
      $this->seed(RolesAndPermissionsSeeder::class);
  });
  ```

#### Skenario yang Diuji

1. **Admin**:

   - Setup:
     - `User::factory()->create();`
     - `assignRole('admin');`
   - Ekspektasi:
     - `GET route('dashboard')` → redirect ke `/admin`.

2. **Editor**:

   - Setup:
     - `assignRole('editor');`
   - Ekspektasi:
     - `GET route('dashboard')` → redirect ke `/admin`.

3. **Writer**:

   - Setup:
     - `assignRole('writer');`
   - Ekspektasi:
     - `GET route('dashboard')` → redirect ke `/admin`.

4. **Subscriber – profil belum lengkap**:

   - Setup:
     - `assignRole('subscriber');`
     - Tanpa mengisi field profil wajib.
   - Ekspektasi:
     - `GET route('dashboard')` → redirect ke `route('profile.edit')`.

5. **Subscriber – profil lengkap**:

   - Setup:
     - `assignRole('subscriber');`
     - Mengisi semua field profil wajib:
       - `wa`, `nik`, `tempat_lahir`, `tanggal_lahir`, `alamat_lengkap`,
       - `s1_fakultas`, `s1_prodi`, `s1_tahun_masuk`, `s1_tahun_tamat`.
   - Ekspektasi:
     - `GET route('dashboard')` → redirect ke `route('dashboard.subscriber')`.

---

### 14.6. Hubungan Fase 10 dengan Fase Sebelumnya

- Fase 1–9 mendefinisikan **desain RBAC dan UX dashboard**:
  - Siapa diarahkan ke `/admin`.
  - Siapa yang memiliki akses ke dashboard subscriber.
  - Kewajiban melengkapi profil sebelum mengakses area tertentu.
- Fase 10 **tidak mengubah desain** ini, hanya:
  - Menambah test otomatis yang:
    - Mengkonfirmasi bahwa implementasi route `/dashboard` mengikuti blueprint.
    - Menjadi “sinyal bahaya dini” jika di masa depan ada perubahan yang tidak sengaja.

Dengan kata lain:

- Sebelum Fase 10:
  - RBAC dashboard “terlihat benar”.
- Sesudah Fase 10:
  - RBAC dashboard memiliki **regression guard** melalui test otomatis.

---

### 14.7. Catatan Tentang Test Lain

- Saat menjalankan `php artisan test`, terdapat beberapa kegagalan yang **tidak** terkait Fase 10:
  - Test Fortify/Settings lama yang mengasumsikan adanya route:
    - `profile.destroy`
    - `two-factor.show`
  - Di aplikasi nyata Anda, route-route tersebut memang sudah tidak (atau belum) digunakan.
- Keputusan:
  - Fase 10 **tidak menyentuh** behavior login/two-factor lama.
  - Penanganan test Fortify/Settings akan diperlakukan sebagai bagian dari **track “Login Case / Settings Hardening”**, bukan bagian dari Fase 10 RBAC dashboard.

---

### 14.8. Ringkasan Fase 10

- Menambahkan test yang mengunci perilaku:
  - `/dashboard` → `/admin` untuk admin/editor/writer.
  - `/dashboard` → `profile.edit` untuk subscriber yang profilnya belum lengkap.
  - `/dashboard` → `dashboard.subscriber` untuk subscriber dengan profil lengkap.
- Menyelaraskan test `DashboardTest` dengan flow redirect baru.
- Tidak mengubah desain RBAC, hanya **menguatkan** dengan regression test.
