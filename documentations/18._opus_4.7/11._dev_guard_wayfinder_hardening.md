# Dev Guard + Wayfinder Hardening (Permanent)

## Tujuan

Mencegah kejadian berulang saat development:

1. `npm run dev` berjalan lebih dari satu instance (double server, restart loop, state tidak stabil).
2. Wayfinder generate output yang memicu watcher Vite, lalu server restart berulang dan terasa `Warming Up` terlalu lama.

## Perubahan yang Diterapkan

### 1) Single-instance guard untuk dev server

File: `scripts/dev-single-instance.mjs`

- Menambahkan lock file di:
  - `storage/framework/cache/dev-locks/vite-dev.lock.json`
- Saat `npm run dev` dijalankan:
  - Cek lock lama.
  - Cek proses aktif berdasarkan PID lock.
  - Validasi PID lock benar-benar proses `vite` untuk project path saat ini.
  - Jika valid, proses baru ditolak.
  - Jika lock stale, lock dibersihkan otomatis.
- Menambahkan fallback deteksi proses `vite` aktif by project path:
  - Windows: `Get-CimInstance Win32_Process`.
  - Non-Windows: `ps -ax -o pid=,command=`.
- Menambahkan opsi `--force`:
  - `npm run dev -- --force`
  - Opsi ini dipakai untuk membersihkan lock stale dengan aman.
  - Tetap tidak akan membiarkan instance kedua jika proses `vite` aktif untuk project yang sama.

### 2) Integrasi script ke npm

File: `package.json`

- `dev` diubah menjadi:
  - `node scripts/dev-single-instance.mjs`
- Ditambahkan alias bypass:
  - `dev:vite` tetap langsung ke `vite` (untuk kebutuhan troubleshooting tertentu).

### 3) Watch ignore untuk output generated Wayfinder

File: `vite.config.ts`

Menambahkan `server.watch.ignored`:

- `**/resources/js/actions/**`
- `**/resources/js/routes/**`
- `**/resources/js/wayfinder/**`

Tujuan: mencegah perubahan file hasil generate Wayfinder memicu restart watcher dev berulang.

## Diagnosa Masalah yang Ditemukan Saat Implementasi

1. Implementasi awal guard sempat gagal di Windows (`spawn EINVAL`).
   - Disesuaikan agar launch Vite kompatibel di environment Windows.
2. `Warming Up` lama juga dipengaruhi oleh:
   - restart akibat generate Wayfinder;
   - task `tsc --noEmit` yang memunculkan error `TS6053` masif karena banyak file route generated tidak ada.
3. Lock stale dengan PID yang masih hidup tapi bukan proses Vite project yang sama dapat memicu false positive.
   - Sudah diatasi dengan validasi command line proses berdasarkan project path.

## Cara Pakai Operasional

### Normal

```bash
npm run dev
```

### Jika lock dianggap stale

```bash
npm run dev -- --force
```

Catatan:

- `--force` bukan untuk override proses Vite aktif.
- Jika Vite aktif untuk project yang sama, guard tetap menolak start kedua.

## Verifikasi yang Sudah Dilakukan

1. Smoke test launcher:
   - `node scripts/dev-single-instance.mjs --version` berhasil menjalankan Vite CLI version.
2. Guard saat instance aktif:
   - Menjalankan ulang command saat dev aktif menampilkan pesan penolakan single-instance.
3. Pemeriksaan lint:
   - Tidak ada lint error baru pada file guard dan konfigurasi terkait.

## Catatan Lanjutan (Opsional)

- Jika dibutuhkan, bisa ditambah mode khusus untuk menutup proses Vite lama secara otomatis (opt-in eksplisit), tetapi saat ini sengaja tidak diaktifkan demi keamanan proses development.
