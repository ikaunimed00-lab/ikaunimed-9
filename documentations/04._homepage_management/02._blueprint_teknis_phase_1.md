# Blueprint Teknis Phase 1: Manajemen Homepage & Global Settings

Dokumen ini merinci arsitektur teknis untuk implementasi sistem manajemen konten dinamis pada Homepage dan Pengaturan Global IKA UNIMED.

## 1. Arsitektur Database

Kita akan menggunakan dua tabel utama untuk memisahkan pengaturan global yang bersifat statis dengan konten homepage yang bersifat blok (dinamis).

### A. Tabel `site_settings`
Digunakan untuk menyimpan konfigurasi global yang muncul di hampir semua halaman (Header, Footer, SEO).

| Kolom | Tipe | Deskripsi |
| :--- | :--- | :--- |
| `id` | BigInt (PK) | Primary Key |
| `key` | String (Unique) | Kunci unik (contoh: `site_logo`, `contact_email`) |
| `value` | Text/LongText | Nilai dari kunci tersebut (bisa string atau JSON) |
| `type` | String | Tipe input (text, image, textarea, json) |
| `group` | String | Pengelompokan (identitas, kontak, sosmed, footer) |

### B. Tabel `homepage_sections`
Digunakan untuk manajemen blok konten pada landing page dengan sistem *Block-Based CMS*.

| Kolom | Tipe | Deskripsi |
| :--- | :--- | :--- |
| `id` | BigInt (PK) | Primary Key |
| `type` | Enum | Tipe blok (`hero`, `cta`, `video`, `features`, `packages`) |
| `title` | String | Judul internal untuk manajemen admin |
| `content` | JSON | Data konten fleksibel (array slide, deskripsi, link, icon) |
| `order` | Integer | Urutan tampilan di homepage |
| `is_active` | Boolean | Status aktif/nonaktif blok |

## 2. Struktur Manajemen Filament (Admin Panel)

### A. Global Settings (Akses: Admin Pusat Saja)
Menu ini akan menggunakan halaman kustom atau Resource tunggal untuk mengelola:
- **Identitas**: Logo, Favicon, Nama Situs, Slogan.
- **Kontak**: WhatsApp, Email, Alamat Fisik.
- **Sosial Media**: Instagram, Facebook, YouTube, LinkedIn.
- **Footer**: Teks Copyright, Deskripsi Singkat Footer.

### B. Homepage Management (Akses: Admin Pusat & Editor Pusat)
Menggunakan Resource dengan fitur `reorderable()` dan `toggleable()`:
- **Hero Slides**: Mengelola gambar background, judul besar, dan tombol CTA pada carousel.
- **Quick Links (CTA)**: Mengelola kartu akses cepat di bawah hero.
- **Section Content**: Mengelola teks dan media untuk Video, Fitur, dan Paket Unggulan.

---

## 3. Strategi Implementasi

### A. Phase 1: Fondasi & Dinamisasi
1. **Migrasi & Model**: Membuat tabel dan model dengan *casting* JSON pada kolom `content` dan `value`.
2. **Data Seeding**: Mengekstrak konten statis dari file React saat ini (`Index.tsx`, `HeroCarousel.tsx`, dll) ke dalam database agar sistem langsung siap pakai.
3. **Filament Integration**: Membangun UI manajemen di admin panel.
4. **Frontend Integration**: Mengubah `Index.tsx` agar menerima data dari `HomepageController` melalui props Inertia.

### B. Optimasi (Caching Layer)
Untuk menjaga performa, data dari `site_settings` dan `homepage_sections` akan disimpan dalam **Laravel Cache**.
- Cache akan di-*clear* otomatis setiap kali ada perubahan data di admin panel.
- Query database hanya terjadi satu kali (saat cache kosong).

---

## 4. Keamanan & Validasi
- **Image Validation**: Batasan maksimal 2MB dengan optimasi otomatis ke format WebP.
- **Access Control**: Memastikan Editor Daerah (DPW/DPC) tidak memiliki akses ke pengaturan Homepage Nasional.
