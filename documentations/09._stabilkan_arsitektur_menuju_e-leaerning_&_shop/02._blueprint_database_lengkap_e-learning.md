# 1️⃣ CORE ENTITY

## 📘 1. courses

Mewakili satu program pembelajaran.

```sql
id
title
slug (unique)
excerpt
description (longtext)
thumbnail
level (beginner/intermediate/advanced)
category_id (nullable)
instructor_id (nullable, FK users)
price (decimal 12,2 default 0)
is_paid (boolean default false)
status (draft/published/archived)
published_at (nullable)
duration_minutes (nullable)
created_at
updated_at
```

### Catatan Arsitektur:

* `is_paid` dipisah dari price agar mudah filter free vs paid.
* `status` penting untuk kontrol publikasi.
* `instructor_id` FK ke users (role instructor).
* `slug` untuk SEO & route binding.

---

## 🎬 4. lessons

Satu module punya banyak lesson.

```sql
id
course_module_id (FK)
title
slug
content_type (video/pdf/text/embed)
content (longtext) 
video_url (nullable)
file_path (nullable)
duration_minutes (nullable)
order_number
is_preview (boolean default false)
created_at
updated_at
```

### Kenapa pisahkan content_type?

Agar fleksibel:

* video upload
* youtube embed
* pdf
* text article

Jangan gabungkan jadi satu kolom ambigu.

# 3️⃣ USER INTERACTION

## 🎓 5. enrollments

Mewakili user mengikuti course.

```sql
id
user_id (FK users)
course_id (FK courses)
status (active/completed/cancelled)
progress_percentage (integer default 0)
started_at (nullable)
completed_at (nullable)
created_at
updated_at
unique (user_id, course_id)
```

### Kenapa simpan progress_percentage?

Agar:

* Tidak perlu hitung ulang setiap load
* Dashboard lebih cepat

---

## 📊 6. lesson_progress

updated_at

Ini granular tracking.
