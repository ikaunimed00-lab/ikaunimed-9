# Resume Blueprint E‑Shop IKA UNIMED

## 1. Tujuan & Lingkup

- Membangun E‑Shop resmi IKA UNIMED (single‑vendor) untuk:
  - Merchandise fisik alumni.
  - Produk digital (rekaman webinar, e‑book, akses kursus, layanan).
- Menjaga konsistensi dengan arsitektur hybrid yang sudah ada:
  - Filament = Governance Layer (manajemen katalog, pesanan, laporan).
  - Inertia = Application Layer (frontstore, cart, checkout).
- Menggunakan Spatie (role + permission) sebagai satu‑satunya sumber kebenaran akses.
- Mengintegrasikan pembayaran via Tripay dengan standar keamanan Midtrans (webhook + signature).


## 2. Asumsi Arsitektur Utama

- Single‑vendor (toko pusat IKA), tetapi:
  - Kolom `organization_id` disiapkan sejak awal di `products` dan `orders` untuk mendukung skenario DPW/DPC di masa depan.
- RBAC:
  - Namespace permission baru: `shop.*`.
  - `users.role` hanya legacy/fallback, tidak dipakai untuk akses Shop.
- Layering tegas:
  - Filament hanya untuk governance (product/order/payment/settings).
  - Inertia untuk pengalaman belanja (katalog, cart, checkout, riwayat order).


## 3. Domain & Model Inti (Ringkas)

| Domain      | Model              | Fungsi utama                                        |
|------------|--------------------|-----------------------------------------------------|
| Catalog    | `Product`          | Produk yang dijual (physical/digital/service).     |
| Catalog    | `ProductCategory`  | Kategori produk.                                    |
| Catalog    | `ProductImage`     | Gambar tambahan produk.                             |
| Cart       | `Cart`, `CartItem` | Keranjang belanja per user (DB‑based).             |
| Order      | `Order`            | Header pesanan user.                                |
| Order      | `OrderItem`        | Detail item di dalam order (snapshot harga/stok).  |
| Payment    | `Payment`          | Rekaman transaksi ke Tripay/Midtrans.              |
| Payment    | `PaymentLog`       | Log mentah callback/webhook (audit).               |
| Config     | `ShopSetting`      | Konfigurasi global shop.                            |
| (Next)     | `Shipment`         | Data pengiriman fisik (kurir, resi).               |

Field penting (garis besar):

- `products`: `name`, `slug`, `description`, `price`, `compare_at_price`, `stock`, `is_active`, `type` (`physical/digital/service`), `category_id`, `organization_id` (nullable).
- `orders`: `user_id`, `organization_id`, `status`, `fulfillment_status`, `total_amount`, `shipping_cost`, `grand_total`, `shipping_address` (JSON), `notes`, `created_by`, `updated_by`.
- `payments`: `order_id`, `provider`, `provider_reference`, `method`, `amount`, `status`, `paid_at`, `raw_payload`.


## 4. Status Model

**Order.status** (lifecycle finansial):

- `draft`
- `awaiting_payment`
- `paid`
- `fulfilled`
- `canceled`

**Order.fulfillment_status** (lifecycle pemenuhan):

- `unfulfilled`
- `processing`
- `shipped`
- `completed`

**Payment.status**:

- `pending`
- `paid`
- `failed`
- `expired`

Prinsip: payment lifecycle dan fulfillment lifecycle dipisah agar aman untuk skala besar dan fitur lanjut (pre‑order, partial shipment, digital access).


## 5. Permission Matrix `shop.*` (Ringkas)

Permission utama:

- Produk & kategori:
  - `shop.product.view`
  - `shop.product.manage`
  - `shop.product.publish`
  - `shop.category.manage`
- Order & fulfillment:
  - `shop.order.view`
  - `shop.order.manage`
  - `shop.order.refund`
  - `shop.order.export`
- Payment:
  - `shop.payment.view`
- Pengaturan:
  - `shop.settings.manage`

Contoh mapping role Spatie:

- `admin`: semua `shop.*`.
- `editor_shop`: `shop.product.view`, `shop.product.manage`, `shop.category.manage`.
- `shop_operator`: `shop.order.view`, `shop.order.manage`.
- `finance`: `shop.payment.view`, `shop.order.view`, `shop.order.export`.
- `subscriber`: tidak memiliki `shop.*`; hak sebagai pembeli diatur lewat policy (owner‑based).


## 6. Pemetaan UI: Filament vs Inertia

**Filament (Governance):**

- `Shop\ProductResource`
  - `canViewAny()` → `can('shop.product.view')`.
  - Create/Edit/Delete → `can('shop.product.manage')`.
  - Publish/Unpublish → `can('shop.product.publish')`.
- `Shop\ProductCategoryResource`
  - Akses penuh → `can('shop.category.manage')`.
- `Shop\OrderResource`
  - Lihat pesanan → `can('shop.order.view')`.
  - Ubah status order → `can('shop.order.manage')`.
- `Shop\PaymentResource`
  - Lihat pembayaran → `can('shop.payment.view')`.
- `Shop\ShopSettingResource`
  - Konfigurasi shop → `can('shop.settings.manage')`.

**Inertia (Application / Frontstore):**

- `GET /shop` → katalog produk aktif.
- `GET /shop/{product:slug}` → detail produk.
- `GET /shop/cart` → cart user (DB `Cart` + `CartItem`).
- `POST /shop/cart` dsb. → operasi menambah/mengubah cart.
- `GET /shop/checkout` + `POST /shop/checkout` → membuat `Order` + `Payment`, memanggil Tripay.
- `GET /shop/orders` + `GET /shop/orders/{order}` → riwayat dan detail pesanan user (policy owner‑based).

Integrasi sidebar Inertia:

- Tambah grup `SHOP / MARKETPLACE` yang menampilkan link ke `/shop` untuk user yang sudah siap checkout (subscriber/learner dengan profil lengkap), tetap mengikuti pola `SIDEBAR_MENU` berbasis permission/policy.


## 7. Alur Payment Tripay + Webhook (Ringkas)

1. User checkout:
   - Backend buat `Order` (`status = awaiting_payment`).
   - Backend buat `Payment` (`status = pending`), panggil API Tripay, simpan `provider_reference`, redirect ke payment URL.
2. Tripay panggil webhook, misalnya `POST /webhook/tripay/shop`:
   - Verifikasi signature.
   - Temukan `Payment` via `provider_reference`.
   - Update `Payment.status` dan `paid_at`.
   - Update `Order.status` (misalnya `awaiting_payment` → `paid` atau `canceled`).
   - Simpan payload di `PaymentLog`.
3. Webhook harus idempotent:
   - Jika `Payment.status` sudah `paid`, callback berikutnya diabaikan.


## 8. Roadmap Implementasi (Tahapan)

1. **Fase 1 – Katalog Produk (Read‑only)**
   - Migrasi `product_categories`, `products`, `product_images`.
   - Filament: `ProductResource`, `ProductCategoryResource` dengan `shop.product.view/manage` dan `shop.category.manage`.
   - Inertia: `/shop` dan `/shop/{slug}` (tanpa checkout).

2. **Fase 2 – Cart & Order Basic (DB Cart)**
   - Migrasi `carts`, `cart_items`, `orders`, `order_items`.
   - Implementasi cart DB‑based dan checkout lokal (status `awaiting_payment` tanpa Tripay dulu).

3. **Fase 3 – Integrasi Tripay (Sandbox → Live)**
   - Migrasi `payments`, `payment_logs`.
   - Integrasi API Tripay (sandbox), kemudian live.
   - Implementasi webhook dengan verifikasi signature + idempotensi.
   - Tambah `Shop\OrderResource` dan `Shop\PaymentResource` di Filament.

4. **Fase 4 – Fulfillment & Shipment**
   - Tambah model `Shipment` dan field `fulfillment_status` di `orders`.
   - Workflow pengiriman & penerimaan barang.

5. **Fase 5 – Produk Digital & Integrasi LMS**
   - Gunakan `products.type = digital` untuk produk digital.
   - Setelah `Payment.status = paid`, grant access ke LMS atau konten digital sesuai tipe produk.


## 9. Integrasi dengan RBAC & Dashboard Eksisting

- Semua resource Shop di Filament dikontrol via permission `shop.*`.
- Tidak ada logic Shop yang bergantung pada kolom `users.role`.
- Dashboard Inertia tetap mematuhi pola:
  - Data user (role/permission) dikirim melalui Inertia share (`HandleInertiaRequests`).
  - Menu `/shop` hanya muncul jika user memenuhi policy (profil lengkap, bukan banned, dsb.).
